DESIGN NOTE

A stage-optimal Roux solver is small enough to brute force.

Roux has four natural stages: first block, second block, CMLL, and last six edges. Each can be searched independently and stored as a compact policy. That gives RouxLab an exact baseline for measuring what a learnable pattern set costs.

01 · FB

First block

5,322,240

Abstract states for its three edges and two corners. Explicitly tracking which movable center was selected raises the upper estimate to about 31.9 million.

02 · SB

Second block

1,088,640

States for the remaining three block edges and two corners with first block fixed. Tracking the four M-axis center offsets gives an upper estimate of 4,354,560.

03 · CMLL

Top corners

648

Concrete corner cases: 4! × 3³. AUF and symmetry reduce these to the familiar named cases, but a computer can simply retain all 648.

04 · LSE

Last six edges

184,320

The exact M/U-reachable orbit, including edge permutation and orientation, center offset, and corner AUF. The generated policy has maximum depth 20 STM and occupies about 720 KiB.

THE BASIC MECHANISM

Rank, look up, move, repeat.

Generate each table offline by searching backward from its goal states. Encode the relevant cubies directly as an integer rank. Each entry then stores the next move—and optionally the remaining distance—on a shortest path.

This is an exact, constant-time lookup. A textual pattern scan, general-purpose hash table, or Bloom filter would only add overhead. Bloom filters are especially unsuitable because they admit false positives and do not return the required action.

IMPORTANT QUALIFICATION

CMLL has 648 inputs, not necessarily a 648-state search.

A CMLL algorithm may temporarily disturb block pieces and restore them at the end. A search over ordinary turns must therefore track enough of the cube to verify that both blocks return solved; corner state alone is not Markov under those moves.

There are two practical approaches: search the 648 starting cases with IDA* and good block-preservation heuristics, or construct a smaller graph from block-preserving macro moves. The finished policy still needs only one result per concrete CMLL input.

BOUNDARIES

Optimal by stage is not globally optimal.

Each table minimizes its own stage without looking ahead. The shortest first block can lead to a worse second block, and the shortest CMLL can lead to a worse LSE. That is intentional: it models recognizable Roux decisions and produces a fair, reproducible reference.

Color neutrality should compare first-block cost only. Pair order should compare completion of that block only. CMLL may leave an AUF, and LSE should absorb that alignment rather than charging CMLL for it.

POLICY COMPRESSION

Can the table be reduced to rules plus exceptions?

Once the exhaustive policy exists, it becomes training data. We can search for compact machine rules that select an optimal next move across large groups of states, then retain an exact exception table for the states that resist compression.

EXACT POLICY→GENERAL RULES→SPECIALIZED RULES→EXCEPTIONS
01

Preserve every optimal choice

A BFS should retain every move that decreases the exact distance by one, not just its arbitrary parent move. A compressed rule may choose any of them, greatly increasing the structure it can share.

02

Require exact coverage

A rule is accepted only where its action is provably optimal. States outside its domain continue to more specific rules or the exception table. Nothing is guessed and no state silently falls back.

03

Optimize machine cost

The rules need not be understandable to a cuber. Decision DAGs, bit predicates, arithmetic programs, symmetry reduction, and small indexed subtables are all valid if they reduce bytes without making lookup impractical.

Measure the whole representation.

Score rule bytecode, exception keys and actions, and evaluation cost together. Compare the result with a dense packed table—and with that table after Brotli compression—because a clever rule system is only useful if it beats the simple baseline in a meaningful way.

WHAT THIS ENABLES

Measure the price of learnability.

The exhaustive policies become a control group. RouxLab can compare beginner pairs, direct pairs, two-look CMLL, full CMLL, direct EO, EOLR, and other human-sized algorithm sets against the shortest solution available inside the same stage boundaries.
